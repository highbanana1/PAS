# PAS PvP 个人撤离联机实现规格

状态：已确认设计的实现规格；联机功能尚未实现。

## Problem Statement

PAS 目前拥有可玩的单机移动、枪械、剑、格挡、分格生命、死亡复活、物品与星星交桌玩法，但这些行为由本机节点直接驱动，没有多人会话、可信的统一裁决、跨客户端稳定身份或断线恢复。直接把节点状态广播给其他玩家会产生命中不一致、重复拾取、星星归属分裂、房主与客户端走不同规则，以及摄像机影响弹丸寿命等问题。

玩家需要一个面向 PC 本机双开与局域网的个人撤离 PvP 模式。有限数量的星星代表有限撤离名额；一局可以有多名玩家分别撤离成功，未取得名额者在整局结束时失败。

## Solution

建立三个深模块，以小接口隐藏联网复杂度：

- **MatchAuthority**：唯一权威比赛规则模块。接收已绑定发送者身份的命令，按固定物理步进推进移动、战斗、物品、星星、撤离、死亡复活和比赛结束，输出权威 snapshot 与 domain event。
- **NetworkSession**：ENet 会话 adapter。负责建房、加入、peer 到稳定玩家身份的映射、席位、重连、baseline、通道与消息投递；不决定伤害、归属或胜负。
- **ClientView**：客户端输入与表现模块。采样本地输入、预测本地移动和攻击表现、插值远端角色、更新 HUD 与观战画面，并接受权威纠正。

房主本地玩家与远端玩家使用相同命令队列和裁决路径。单机模式通过离线 adapter 使用同一个 MatchAuthority，避免维护两套玩法规则。

## User Stories

1. 作为房主，我可以创建最多 16 席的局域网房间，并让本机或局域网玩家加入。
2. 作为客户端，我不能通过伪造玩家身份、位置、伤害、命中、时间或胜利结果改变比赛。
3. 作为房主玩家，我的输入也必须经过相同的权威校验，不能获得绕过规则的本机路径。
4. 作为本地玩家，我的移动立即产生预测反馈，并在与服务器不一致时平滑纠正。
5. 作为观察远端玩家的客户端，我看到经过插值的移动，而不是直接使用远端键盘输入或本机物理状态。
6. 作为霰弹枪玩家，我每次射击仍产生 5 颗独立弹丸，并保持现有伤害与约 15 度集中散射。
7. 作为被霰弹命中的玩家，我受到每颗弹丸的独立攻击，多个弹丸不会合并成一次伤害。
8. 作为射击双方，我得到按可见弹丸大小校准、使用连续碰撞并以最近碰撞为准的权威命中结果。
9. 作为剑与格挡玩家，我保留当前攻击、格挡、耗尽锁定、恢复及攻击取消格挡的语义。
10. 作为受伤玩家，我保留生命格吞掉单次攻击超额伤害的规则。
11. 作为死亡玩家，我在世界继续运行时等待 5 秒复活，复活为五格生命并刷新现有角色状态。
12. 作为物品持有者，我死亡时背包与携带星星只掉落一次，其他玩家看到一致结果。
13. 作为参赛者，我可以拾取一颗自由星星并将它交给一个空闲撤离点。
14. 作为交付者，我在撤离点停留 30 秒；普通受伤不打断，离开会清零并把星星退回携带状态。
15. 作为交付者，我在读秒中死亡时，BOUND 星星从撤离点解绑并掉在死亡位置。
16. 作为完成读秒的玩家，我消耗星星、取得个人胜利、退出战斗并进入观战，其他玩家继续本局。
17. 作为同刻完成撤离并受到致死攻击或到达 10 分钟截止的玩家，我的撤离成功先结算；此前已死亡或已离开区域则不成功。
18. 作为中途加入者，我可以直接参战，但不会增加按开局人数确定的星星配额。
19. 作为断线玩家，我的角色留场并可受攻击，席位为我保留 30 秒，重连后恢复当前权威状态。
20. 作为断线玩家，我的死亡复活、撤离读秒和重连保留期按已确认规则并行运行，也可以在离线期间完成撤离。
21. 作为断线超时玩家，我的角色被移除，物品、星星与撤离点清理只执行一次；之后再次连接按中途加入处理。
22. 作为正在重连的玩家，我的保留席位不会被新加入者占用；满员时新的中途加入会被拒绝。
23. 作为参赛者，我知道本局在 10 分钟截止、全部星星消耗或所有参赛者离场时结束，未撤离者失败。
24. 作为地图作者，我可以配置撤离点与普通敌人；首张 PvP 验证地图不生成普通敌人。
25. 作为单机玩家，我在离线 adapter 接入后仍获得与当前版本相同的枪、剑、格挡、物品、生命与复活效果。

## Implementation Decisions

- MatchAuthority 的 interface 只暴露比赛配置、命令入队、固定步进、按玩家生成 snapshot、以及读取 domain event。内部状态机、碰撞、计时和幂等细节不泄漏给调用者。
- NetworkSession 从实际 RPC 发送 peer 推导玩家身份。命令只携带操作意图与序列，不接受客户端提交的最终位置、伤害、命中、时间、随机数或胜负。
- 使用稳定的 match、player、entity、item、life、action、shot 与 revision 标识。旧比赛、旧生命和重复事件必须可识别并拒绝；不跨网络传递 Node、Resource、RID 或本机 instance ID。
- late join 与重连先接收同一权威时刻生成的完整 baseline，再接收该时刻之后的事件。跨可靠与不可靠通道不依赖到达顺序，而以 epoch、revision 和幂等事件标识收敛。
- 生成、销毁、伤害、死亡、拾取、交付、撤离和比赛结果使用可靠事件；高频输入与 snapshot 可以使用不可靠有序通道。
- 权威物理从 60 Hz、snapshot 从约 20 Hz 作为初始压测参数开始；它们是可调起点，不是已验证性能或硬性完成指标。
- CharacterMotor 的显式移动命令继续作为移动规则入口。本地玩家预测自己的移动，服务器重演命令并纠正；远端玩家插值。首版 LAN 不做历史回滚或服务器倒带命中补偿。
- 服务器为每次有效开火生成真实的 5 颗弹丸方向与速度，并以 shot 标识关联客户端预测表现。弹丸使用固定步进扫掠、可见尺寸碰撞、最近碰撞排序和权威生命周期，不能由任何摄像机的屏幕退出事件销毁权威弹丸。
- 每颗弹丸独立产生攻击。分格生命继续对每次攻击吞掉当前格以外的超额伤害，不能为了节省网络消息把多颗弹丸聚合成一次攻击。
- 剑击使用稳定目标、生命与挥砍标识去重；格挡方向、格挡状态、格挡条与伤害均由权威状态验证。现有接触伤害无敌时间不会自动扩大到枪械或剑伤害。
- 网络物品只同步稳定物品标识、类型、剩余量、容量、归属和 revision。图标、脚本资源、弱引用等只属于本地表现或运行时绑定。
- 星星严格处于 FREE、CARRIED、BOUND、CONSUMED 之一。撤离点占用由唯一 BOUND 记录派生；星星守恒以开局生成总数为准。
- 同一权威步进内先验证玩家此前仍存活且仍在区域，再提交已满 30 秒的撤离；其成功先于同刻致死伤害和 10 分钟截止。随后结算其余伤害、死亡和整局结束。
- 断线保留、死亡复活和撤离计时使用权威时钟并可并行。重连恢复当前状态，不回滚到断线前快照。超时清理必须幂等，已经因死亡掉落的内容不能再次生成。
- 房间最多 16 个席位，参赛者、观战者和保留角色均计入。保留席位锁定给原玩家；只有期满清理后才释放。
- 房主退出即结束房间。首版不做主机迁移。

## Testing Decisions

测试只跨三个已确认 seam，断言外部行为而不测试内部私有类：

1. **MatchAuthority interface**：给定规则、地图描述、确定性时钟与命令序列，观察 snapshot 与 domain event。它捕获比赛、星星、战斗、计时、重连和结算优先级，但不证明真实 ENet 或视觉手感。
2. **NetworkSession 本机集成 seam**：启动真实 Godot ENet host 与至少一个 client，验证发送者身份、baseline、事件幂等、断线重连、席位和双端最终一致；不以它验证像素表现。
3. **现有 SceneTree 行为回归 seam**：保留现有 29 组单机测试，确保离线 adapter 不破坏枪、剑、格挡、物品、生命格和复活；它不能代替联机规则测试。

每个实现任务遵循一条失败行为测试、一个最小实现、再进入下一条的纵向 red-green 循环。测试使用公开 interface 和已知输入输出，不复制实现算法，也不为浅包装添加测试。

## Out of Scope

- 专用服务器。
- 公网匹配、房间发现、NAT 穿透或中继。
- 主机迁移。
- 跨平台联机。
- 历史回滚、服务器倒带命中补偿。
- 数据库账号系统和反作弊承诺。
- 以 60 Hz/20 Hz 或 16 人作为未经实测的性能保证。
- 修改 `develop` 或 `master` 的稳定基线。

## Further Notes

- 本规格定义实现目标，不代表联机功能已经完成。
- 现有单机代码是兼容目标，不是可以直接广播的网络模型。迁移采用扩展再收缩：先让离线 adapter 与旧入口并存，逐个纵向切片迁移，最后在完整回归和联机验收通过后删除旧的直接结算入口。
- 首个可玩里程碑是两进程完成移动、战斗、拾星、交付、死亡取消与一人撤离；16 人承载与网络条件测试位于最后收口阶段。
