实现 frontier 当前为 08。每个任务使用自己的失败行为测试和最小实现；完成并验证后才解除下一条阻塞边。

Ticket 05 已在 `MatchAuthority` 接入星星 FREE/CARRIED/BOUND/CONSUMED 状态及地图撤离点。默认读秒 30 秒，离开返还给交付者、死亡落在死亡位置；读秒到点与同刻致命剑击并发时撤离先结算。获胜者转观战，其他人继续。本地双进程 ENet 测试验证客户端拾星交付与双方收敛，地图节点测试验证现有星星与桌子的联机自动交互及会话结束后单机入口恢复。

Ticket 06 保留断线者角色与席位 30 秒；房主继续裁决受击、复活和撤离，超时一次性清理角色、背包和星星。重连只接受原客户端保存的私有随机凭据，恢复同一身份时更换凭据，并发送当前权威 baseline。客户端可暂存 `NetworkSession.get_local_identity()`，重连时作为 `join(address, port, saved_identity)` 第三个参数；其中的 `reconnect_token` 不应写入仓库、广播或普通日志。实际地图的房间入口与角色生成由 Ticket 07 接入，当前测试夹具负责创建联机角色。

Ticket 07 增加独立入口 `res://scene/pvp_main.tscn`，保留原单机入口。房主在开局时按当时参赛人数冻结星星配额 `ceil(人数 / 4)`，人数上限 16，地图候选星星最多启用 4 颗，其余隐藏。中途加入不增加星星；成功撤离、无人参赛、10 分钟到时分别结算。成功者退出战斗后可按 Tab 切换观战目标。三进程本机 ENet 验证了开局配额、晚加入和角色复制；完整 16 席稳定性留给 Ticket 08。

Ticket 07 曾在三人局观察到全量 unreliable 快照约 3966 字节、去掉重复 combat 后仍约 1852 字节，均超过当时 ENet 提示的 1392 字节 MTU。现已让高频快照只传移动、预测确认和生命转换字段；完整状态仍由可靠基线与战斗修订流承载。Ticket 08 还须量测 16 人各通道载荷，必要时压缩或分片，再做 16 席压测；在通过前不宣称 16 人可稳定游玩。

外部 API 只接收对应 ticket 所需的代码片段、已确认规则与验收条件，不接收凭据或无关项目内容。其输出按不可信草稿处理，必须由 Codex 核对、运行测试并整合；外部 API 不直接推送仓库。
